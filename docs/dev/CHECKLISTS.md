# チェックリスト

AI が各段階で機械的に確認する項目。人間が最終確認する場所は「人間確認ゲート」（`CLAUDE.md`）。

## コミット前

- [ ] `bin/rubocop` と `bin/rspec` が両方グリーン
- [ ] `git diff` を全部見た（依頼と無関係な変更が混ざっていない）
- [ ] デバッグ残骸がない（puts / binding.irb / console.log 等）
- [ ] 指示されていない UI 文言・機能を追加していない
- [ ] 秘密情報（API Key・パスワード・.env・credentials の内容）が入っていない
- [ ] コミットメッセージが規約どおり（`{type}: 日本語の説明`。`CLAUDE.md` 参照）

## PR 前（pr-ship が実施）

- [ ] 対応する issue がある（なければ先に作る）
- [ ] 動作確認欄は実際に検証した手順だけ。未検証の項目は「未検証」と明記
- [ ] タイトル・本文をユーザーに見せて承認をもらってから push する

## リリース・デプロイ前（人間確認ゲート）

- [ ] ユーザーの明示的な承認がある
- [ ] 元に戻す手段を一文で説明できる（ロールバック手順）
- [ ] DB マイグレーション・Render の環境変数追加の有無をユーザーに伝えた
- [ ] 課金・外部サービス（SendGrid 等）への影響有無をユーザーに伝えた

## セキュリティ（新しい依存・認証・外部通信を触ったとき）

- [ ] `bin/brakeman --no-pager --except EOLRails` を実行し、新規指摘がないか確認した
- [ ] JS 依存を追加・更新したら `bin/importmap audit` を実行した
- [ ] 新しい依存 gem は名前・提供元・更新状況を確認した（タイポスクワット注意）
- [ ] 秘密情報がコード・ログ出力・コミット履歴に出ていない
- [ ] 外部送信（メール・API 呼び出し）の宛先と内容をユーザーが把握している
- [ ] Devise 等の認証まわりを変えたときは、送信される通知メールの文面・件名まで確認した（前例: メールアドレス変更通知の文面バグ）
- [ ] 認証・権限まわりの変更は、権限が「広がる」方向の変更でないか確認した
